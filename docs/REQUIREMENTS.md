# ScribeKit 需求原文

（用户原始需求，实现时以此为准，工程约定见 SPEC.md）

## 项目定位

ScribeKit 是一个开源的作文 IDE，核心理念是用户 100% 主导，AI 只做最苦力的部分。不"一键生成作文"，让用户逐段、逐句、逐半句做决策的写作环境。

## 两大核心 Agent

| Agent | 职责 | 类比 |
|---|---|---|
| Analyzer | 细粒度解析文本：段落→句子→半句，识别结构、逻辑、描写类型、半句间关系，并做语法高亮上色 | LSP 语法分析器 + Syntax Highlight，展示形式还可以有箭头、波浪线、下划线之类的 |
| Scaffolder | 统一处理所有生成与建议：根据光标位置、选中半句、段落类型，生成描写、润色句式、补充细节，只提交"建议 patch" | LSP 代码补全 + 重构 + 修复。用户输入自然语言或者直接开写，比如 `[补一段环境描写]` 就会根据上下文生成，反之就是用户写的一个半句 |

## 文集/文章模型（类比代码工程）

- 文集 = 包（Package）：一个文集下的所有文章属于同一个包，文章之间可以相互引用、相互看见。这个相互看见主要给 Scaffolder 用，负责上下文联系。
- 文章 = 代码源文件：每篇文章是文集中的一个独立文件，也可以不属于任何文集，有自己的标题、梗概（类似元信息，用户编写，丢给 Scaffolder 用于背景信息和草稿）、段落结构。文章有文体，例如诗歌、杂文、散文，还可以继续细分，例如记叙文、议论文。
- 总纲 = 包级配置：整个文集共用的约束、风格、规则，隶属于每个包，跟着包存储。

## 文档层级结构

```
文集（Collection / Package）
├── 总纲（Outline）          # 包级共用约束/配置，也是给 AI 用的
├── 文章（Article / Source File）
│   ├── 标题（Title）
│   ├── 梗概（Draft）        # 用户先写，可以凌乱
│   ├── 段落（Paragraph）    # 每段有类型标签
│   │   ├── 类型：开头段 / 结尾段 / Call Backs / 抒情段 / 转折段 / 普通段
│   │   ├── 句子（Sentence）
│   │   │   ├── 半句（HalfSentence）  # 以标点分割，用户可编辑的最小粒度
│   │   │   │   ├── 描写类型：外貌 / 语言 / 动作 / 心理 / 神态 → Analyzer 上色高亮，或者代词等。通过掰开揉碎来从根本上遣词造句，才能实现文章通顺且没有 AI 味。所有 AI 生成的内容，在插入之前，用户必须分析确认后才可以插入
│   │   │   │   └── 逻辑关系：由 Analyzer 分析半句间的关系
```

## 用户工作流

1. 新建文集 → 填写总纲（可忽略，例如用户只是临时起意写一个小短文）
2. 新建文章 → 用户先写标题和梗概（用户必须先动笔，AI 才有东西可以生成。写作文是为了表述我们的观点，而不是通过大数据预测出我们要说什么）
3. 用户起笔 → 一个自由的光标，例如 Enter 确认放置，Shift+Enter 丢给 agent 去 scaffold；创建段落时可以指定段落类型
4. 人机共写 → Scaffolder 按段类型和用户指令生成建议，用户逐句接受/拒绝/修改；AI 生成完整的句子，用户半句半句地评审
5. Call Backs：例如独立段、独句段，用于吸睛，通常由人来写，是展示创意的地方，也可以在拥有足够上下文后由 Scaffolder 生成

## 核心交互：光标即命令面板

- 非线性写作：创意是跳跃的，不强制从头写到尾，用户可以在任何位置插入删除。
- 参考投喂：用户可以把范文、素材、参考资料喂给 AI 作为生成参考（txt 导入）。不做打分之类没用的功能，做类似 code completion 的 sentence completion。

## Analyzer 高亮（LSP）

按描写功能给句子上色，类似 IDE 语法高亮：外貌、语言、动作、心理、神态各一种颜色；以及根据文法词性标记，比如整篇文章点题的字眼，展示形式有方框、下划线、波浪线等。用户一眼看到文章的“描写分布”，哪些地方缺细节、哪些地方重复。

## 导出

Docx 和 Markdown。

## 核心设计原则

1. 用户 100% 主导：AI 不自动填充，用户必须先写标题和梗概。转折句、冲突句、亮点句主要由用户亲自写，不建议 Scaffolder 生成，Scaffolder 可以给建议。
2. AI 只做苦力：描写生成、句式润色、细节补充交给 Scaffolder；结构、转折、立意由用户把控。
3. Analyzer 只读不写：负责分析 + 高亮上色，不负责生成（类似独立的 LSP，基于 AI）。
4. Scaffolder 统一处理所有写操作：生成、补全、润色、建议全部走它。
5. 所有 AI 输出都是建议：不直接覆盖文本，用户逐条接受/拒绝/合并。

## 其他

- 前端界面类似 VSCode / GoLand 这类 IDE。文章渲染是重中之重：句子编排、高亮、光标。
- 融入专业作文指引：议论文论点论据论证、应试作文结构、多处点题等，需要上网搜集专业语料。
- 前后端用 WebSocket；单用户；Fiber 监听一个端口，提供 /api 和前端静态服务；最终单文件打包。
